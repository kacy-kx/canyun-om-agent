# 载运运维 · 检测智能体（前端原型）

载运设备（车组 / 机车）运维检测智能体的控制台原型，单文件、零依赖，纯前端演示。
含工号登录、四角色权限、字段级工单权限与账号管理页。

## 设计要点

- **三栏常驻**：左导航 54px · 主工作区自适应 · 右智能体 376px，窄屏（≤1320px）右栏转为浮动抽屉
- **视觉密度**：正文 13px / 辅助 11px / 指标 25px，紧凑行高配分隔线，适配值班人员一屏多目标
- **状态色只承载状态**：红=超阈值·停机风险，橙=预警，蓝=信息，绿=正常，不做装饰性彩色卡片
- **结论必须带证据**：每条建议附置信度与可点击的依据（工单原文、规程条款、原始波形、备件库存）
- **人在回路**：智能体只能建议和起草，派单需人工确认，确认后才产生工单

## 身份与权限

原型按「认证 → 授权 → 数据隔离」三层实现，三层不要混为一谈：

1. **认证**只回答「你是谁」。工号为唯一账号，密码与之绑定校验，缺任一项不予受理；失败提示统一，避免被用来枚举工号。
2. **授权**决定「进哪个界面」。角色映射到可进入的视图与可执行的动作，这是功能级权限（RBAC）。
3. **数据隔离**决定「能看到哪些行」。每条业务数据带车组范围标签，查询按会话的 `scope` 过滤；越权请求返回空集而不是「无权限」，避免被用来反推数据是否存在。

> 前端隐藏菜单只是体验优化，不是安全边界——真实系统必须在服务端按令牌里的 `role` 与 `scope` 再校验一次。

工单用「字段归属」表达权限，比「有没有工单页」更精确。状态机为
**待派发 → 待核实 → 待派工 → 处置中 → 待验收 → 已完成**：值班派单，工程师到现场核实后写技术方案，方案提交后工单回到值班队列重排天窗，班组执行并填实做记录，最后由工程师技术验收、值班交路确认双签归档。

## 多模态能力

### 视觉检测（看）
- CAM-01 现场画面 + 扫描线动画 + OSD 叠加（机位、帧率、推理耗时）
- AI 框选 4 类缺陷：漏油（油迹扩散）、螺栓松动（预紧不足）、焊缝裂纹（疑似）、异物侵入，各带置信度
- 点击缺陷框或右侧条目互相定位，并触发智能体视觉诊断流（帧序列调取 → 目标检测 → 基线比对 → 建议）
- 依据弹窗回放识别帧与检测明细表

### 声纹分析（听）
- 声样对比：实时采集（磨损）/ 缺油 / 装配不良 / 健康基线
- 时频图与频谱曲线程序化生成：磨损呈现 BPFO 168Hz 及 2/3 次谐波；缺油呈现 800–1800Hz 宽带抬升；装配不良呈现转频强线谱与幅值调制
- 判定卡给出特征频率对照表与处置建议，磨损态可一键生成工单
- 「试听」按钮用 Web Audio 合成对应故障声样（默认静音，点击才播放，8 秒自动停止）

### PHM 预测性健康管理（算与测）
- 三个部件退化曲线：历史实测（实线）+ 外推预测（虚线）+ 限值线 + 预警点
- 制动闸片 / 轮对踏面 / 蓄电池组的 RUL、建议更换日、预警日（提前 3 天）
- 运用强度滑杆（日均里程 600–1600km）实时重算磨耗速率与 RUL
- 闸片进入预警区间时显示横幅并可一键生成更换工单

### 现场模式（手套 / 嘈杂环境）
- 全部触控目标 ≥ 88px，大字号、高对比色块，戴手套单手可操作
- **紧急停机：长按 3 秒 + 弹窗二次确认**，进度条实时反馈，松开即取消；执行后按钮锁定为「已停机」，等待调度复位
- 一键生成报告 / 呼叫专家（双通道呼叫，接通后自动同步诊断上下文）
- 语音指令记录区留痕（谁、何时、说了什么、执行了什么）

### 全局语音（离线唤醒）
- 左下角麦克风按钮或 `Alt+V`，任意页面呼出
- 唤醒词「小运小运」→ 聆听指令，两阶段状态提示 + 声音反馈
- 支持指令：「报告3号车厢2轴温度异常」（触发诊断）、「调出上个月的维保记录」（工单检索）、「紧急停机」、「生成今天的检修报告」、「呼叫专家」等
- 浏览器授权麦克风时走 Web Speech API 实时识别；未授权或环境不支持时自动降级为离线指令面板（点选指令模拟语音，与真实识别走同一条解析链路）
- 兜底：未匹配的指令自动转对话智能体处理

## 本地预览

直接双击 `index.html`，或：

```bash
python -m http.server 8080
# 打开 http://localhost:8080
```

## 部署到 GitHub Pages

```bash
GITHUB_TOKEN=ghp_xxx REPO_NAME=canyun-om-agent ./deploy.sh
```

脚本会：读取 token 对应账号 → 建仓（已存在则复用）→ 提交并推送 `main` → 开启 Pages → 输出访问地址。

> token 建议使用 fine-grained token，仅授权单个仓库，权限勾选 `Contents: Read and write` 与 `Pages: Read and write`；部署完成后到 GitHub 设置里撤销。
