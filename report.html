背 景

为什么需要这个智能体

运维检测现场的三类真实痛点，决定了它不该是"又一个后台系统"，而是替人盯、替人查、替人起草的智能体。

盯不住

值班人员需要长时间盯着实时看板，一屏要覆盖几十到几百个监测对象，纯人工监视容易精神疲劳、漏看告警。

查得慢

检修工程师要边看手册边提问：规程条款、历史工单、部件履历分散在多个系统里，一次诊断要来回翻查。

链条长

从"发现异常"到"派单、处置、验收"要跨多个岗位，信息传递靠口头和电话，出了问题难以追责到环节。

定位一句话：让值班人员"一屏看全、有事主动推"，让工程师"一句话查完证据"，让每张工单"按工序走完、每步有签字"—— 过去是人适应软件的规则，现在是 AI 听懂人的想法、主动适配人的需求。

四条设计原则

1状态色只代表状态

以白蓝为主色，不加多余装饰，颜色只用来分辨轻重：
红 · 超阈值/停机风险橙 · 预警蓝 · 信息绿 · 正常
值班人员扫一眼颜色就知道轻重缓急。

2结论必须附带证据

所有诊断建议都附带可点击的判断依据：工单原文、规程条款、原始波形、识别帧、备件库存——说到哪一条，就能点开看哪一条。

3人作为回路中的一环

智能体只负责建议和起草工单；派单、停机、更换等动作必须交由人工确认并留痕，确保处理出错时责任对应到人。

4权限按车组与数据范围隔离

按车组和数据范围做行级隔离，避免越权查询全线数据。
（账号与行级隔离属后端能力，当前原型阶段暂不含登录层，接口预留。）

一、UI 设计

现场模式：戴着手套也能用

现场操作人员可能戴着手套、处于嘈杂环境等受限场景，交互必须做到极致简化。

1全局语音唤醒（支持离线）

"唤醒词 + 指令"两阶段交互：先聆听唤醒词，唤醒后再听指令，如"报告 3 号车厢 2 轴温度异常""调出上个月的维保记录"。麦克风未授权时自动降级为离线指令面板，与真实识别走同一条解析链路。

2一键式操作，避免误触

关键功能采用大尺寸色块按钮：紧急停机红色通栏大按钮（长按三秒 + 弹窗确认，松开即取消），生成报告蓝色、呼叫专家绿色、语音唤醒橙色。

3全程留痕

语音指令记录区实时记录：谁、什么时候、说了什么、执行了什么。停机指令记录触发来源（声纹对比或账号落实到个人）。

紧急停机长按 3 秒 · 松开取消
生成报告一键输出当日检修报告
呼叫专家接入专家远程会诊
语音唤醒"小运小运" 常驻监听

三、功能

监测看板 + 检测三模态：看 · 听 · 算

监测看板

实时告警队列按等级排序，待处理事件一眼扫清；支持车组切换与时间区间，异常自动高亮并联动右侧推理流。

看 · 机器视觉

目标检测模型识别踏面裂纹、受电弓磨耗、制动盘缺陷，画面上直接框出缺陷位置与置信度，识别帧可点开作为证据。

听 · 声纹分析

FFT 频谱 + 包络谱按轴承特征频率（BPFO/BPFI/BSF）判型：磨损是外圈线谱、缺油是宽带噪声——一听就知道哪种病。

算 · 寿命预测

退化曲线外推剩余寿命（RUL）：制动闸片、轮对踏面还剩几天到限值，提前 3 天预警，滑杆调里程即联动预测。

三个模态的输出都汇入同一个智能体：值班喊一句"报告 3 号车厢 2 轴温度异常"，智能体自己决定调频谱、查规程还是算寿命，最后给出带证据的结论。

字段按工序开放

每一格该谁填、什么时候能填被状态锁死：待派发阶段看不到"实做记录"入口——跳过工序没有入口，人可能偷懒，状态机不会。

完整的证据链

验收归档时这张单子就是一份完整证据链——哪天倒查，每一步谁签的字都在；结论沉淀回知识库，下次更准。

为什么这版不做角色分权：派单权留在值班一侧，因为它决定的是人力与天窗，而不是技术判断；工程师只对"这台车怎么修"负责。 职责分得开，就不必靠权限表去拦。

四、技术实现

三档技术栈：算法 · 组件 · 设计

项目的技术含量分三档：算法/模型（最硬）、现成组件（选型集成）、设计方法（最软但最值钱）。

算法 / 模型

有数学原理，要训练调参——项目的硬技术
  • 视觉目标检测（YOLO 类）：踏面裂纹、受电弓磨耗、制动盘缺陷
  • 声纹频谱分析：FFT、包络谱、轴承特征频率判型
  • PHM 寿命预测：退化曲线外推 RUL，提前预警
  • 缺陷样本标注：框标定 + 数据增强，模型精度的前提
  • 模型转 ONNX / TensorRT 部署到边缘 GPU

现成组件

别人造好的轮子——选型 + 集成
  • 本地大模型（Qwen，vLLM/Ollama）：听懂人话、组织诊断推理
  • RAG 知识库（向量库 + 嵌入）：规程、工单、履历，结论必须带引用
  • ASR + 唤醒词：「小运小运」两阶段语音交互
  • 工具调用协议：四个受限工具的注册与调度
  • 工业协议接入：MQTT / OPC UA 传感器数据

设计方法

不用买不用训——把业务流程想清楚就是技术
  • 工单状态机：五道工序、字段按工序开放、防跳步防漏签
  • 受限工具调用：查询只读、写只落草稿
  • 告警降噪规则：阈值 + 动态基线，不能什么都问大模型
  • 四条设计原则：状态色只表状态、结论带证据、人在回路
  • 全程留痕：谁、何时、说了什么、执行了什么，可倒查到人
  • 这是最离不开业务理解的部分，证明不是只会调 API
本地推理 · 在线：模型跑在现场边缘设备上，数据不出段、断网的车库里照样能干活——这是运维现场的现实约束。
